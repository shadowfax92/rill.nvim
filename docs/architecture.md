# Rill architecture

Rill is a native, read-only Git review document for Neovim 0.11+. Its continuous stream and focused-file view share unified/split projections. Git comparison/source ownership, source-addressed review data, and window presentation are separate modules. Display rows are never source line numbers.

## Internal contracts

`git.load(opts, callback) -> cancel` asynchronously returns `callback(err, snapshot)`. Options: `cwd`, `mode` (`working`, `staged`, `unstaged`, `branch`, `commit`, `range`), `rev`, `base`, `head`, `merge_base`, `paths`, `max_file_bytes`, `max_changed_lines`. Defaults: working means HEAD to worktree including untracked files; range compares base to head (merge-base only when requested); commit compares first parent to commit, empty tree for root commits. Snapshot: `{root, label, left, right, files, options}`; endpoints are `{kind='commit'|'index'|'worktree'|'empty', rev?, label}`. File metadata: `{id, path, old_path?, status, additions, deletions, patch, binary?, omitted_reason?, old_oid?, new_oid?}`. IDs are stable within a comparison and safe as Lua table keys. Exact filesystem paths come from NUL-delimited metadata, not display headers.

`git.source(snapshot, meta, side, callback) -> cancel` returns `callback(err, source)` for `side='old'|'new'`. Source is `{lines, text, identity, label}`; absent side has empty lines/text. Preserve CRLF/EOF facts, bound source reads, schedule callbacks so callers may touch Neovim. Owned jobs are cancellable; no synchronous waits on UI paths. Metadata/patch must retain binary, rename, mode-only and omitted file entries. Source consumers validate against the parsed patch before hydrating mutable worktree snapshots.

`model.parse(meta) -> file` parses controlled Git patch text. File retains `.meta`, `.hunks`, `.expansion` and optional `.old_source`/`.new_source` line arrays. `model.project(file, layout) -> rows` returns body rows, without file header (view owns header). Each row is `{kind='code'|'gap'|'hunk'|'meta', change='context'|'add'|'delete'|'change'?, old={line,text}?, new={line,text}?, hunk?, key?, text?}`. Unified uses separate delete/add rows; context has both old/new cells. Split pairs changes and missing cells are nil. Gaps include `.key`, old/new range/count as appropriate and `.text`; trailing unknown context can be a loadable gap. `model.hydrate(file, old_lines, new_lines) -> ok, err` validates patch-source consistency, then installs full sources. `model.expand(file, key, edge, count)` reveals from `edge='top'|'bottom'|'all'`; `model.expand_all(file)` reveals all context; `model.collapse(file)` resets expansion. Expanded source retains true old/new lines. These functions are pure Lua except optional vim utility calls; they do not read Git, buffers or windows.

`view` owns session/window lifecycle, adds file headers and `.file` to row entries, materializes code in ordinary scratch buffers, and decorates via cached source maps. Split windows have matching row counts with empty non-source padding. Unified source text contains no presentation prefixes; gutters carry signs/numbers. Stable source anchors preserve position through layout/focus/expansion changes. Header/gap/meta rows are not code. Every async completion checks current session generation and buffer validity before publishing.

Public `require('rill').context(ctx)` resolves Sidekick's captured `{buf,win,row,col,range}` (row/col 1-based; range endpoints `(1,0)`-based inclusive) to `{root,file,spans}` or nil outside Rill. File is metadata. Ordered spans: `{path, absolute_path, side, revision, start_line, end_line, start_col, end_col, lines}`; columns are 0-based with exclusive end. Split selection uses active window's side; unified maps deletion to old and addition/context to new. Group only contiguous same-file/same-side source spans. Range crossings over gaps/files produce separate spans. Exact selected code is snapshotted into spans. File tree/header can resolve a file with empty spans.

`sidekick.attach(buf)` installs buffer-local versions of the user's existing send/comment bindings. `sidekick.send(opts)` uses `{comment?,absolute?,kind='line'|'file',filter?,focus?}` and the existing Sidekick context-template interface. The adapter lazily loads Sidekick and supplies custom context tokens producing proper path/revision/source range and code. It must use normal message rendering so comment previews/drafts keep the context; passing only `opts.text` currently loses that preview. No changes to Sidekick source or agent transports are required. `sidekick.format(context, opts) -> string` is testable independently. Non-Rill buffers retain existing mappings.

`selection.rows(ctx)` delegates visual-cell extraction to Neovim's `getregion` and `getregionpos`, returning touched byte ranges and exact selected text per displayed row. This preserves composing Unicode and partial tab/wide-character selections. The view translates these rows through source cells; selections never derive source rows from buffer row numbers. `source.create(content, address, opts)` owns read-only historical buffers and their source addresses independently of review sessions. Its `context(ctx)` uses the same selection helper and remains valid until the source buffer is wiped.

`cache.new(limit)` maintains a weak-key LRU for full sources and syntax captures. `touch(file)` records use; `prune(files, protected)` evicts unexpanded idle sources above the byte target, preserving patch-owned cells. Visible files, expanded context and active consumers pin their sources. Initial untracked captures participate in the budget; after eviction a reread must pass model hydration checks. Session request handles are removed on completion, because retaining completed callback closures would otherwise pin the same source arrays outside this budget.

`highlight` parses each side as its own complete source and records source-coordinate captures. Redraw callbacks project cached captures only. Capture traversal runs in 4ms/1024-item coroutine slices; continuations cross a real timer turn because chains of `vim.schedule` drain before input/timers on Neovim 0.11. Jobs own and cancel their timers and parsers. Native parsing itself has imperfect scheduling on that version; syntax defaults match the readable-source limit (100000 lines/1 MiB), and users can lower coverage if they prefer stricter latency. Completed captures explicitly invalidate the review windows before repainting, since updating the cache alone does not dirty screen lines. Full-line bands use ranged ephemeral highlights with `hl_eol`; `line_hl_group` is ignored for ephemeral marks on Neovim 0.11. The view passes `syntax_max_lines`/`syntax_max_bytes` through per-file syntax limits.

Review backgrounds use a small theme-derived tint; source text has no intraline overlays or character-diff workers. Comment captures reference Rill-owned copies of their theme groups. Preparing each copy outside redraw preserves its styles and adjusts only insufficient foreground contrast against the context/add/delete palette (4.5:1 target). A registry keyed by source capture name rebuilds these stable copies on ColorScheme, so existing cached captures stay valid and normal source buffers keep their theme colors.

Filetype detection first tries each snapshot's filename. Ambiguous names such as `.ts` need a temporary, unlisted buffer containing that side's bounded source: on Neovim 0.11, the extension detector reads buffer lines even when `contents` is supplied to `vim.filetype.match`. Detection never opens the working file or sets a buffer filetype, and wipes its temporary buffer on success or failure before starting the string parser.

`bar.render` builds a width-aware winbar with key/action labels. Split windows share the legend, and narrow panes discard comparison text before actions. Tab/Shift-Tab cycle the actual comparison file list in both stream and focus; `gs` changes layout.

## Verification

Specs return a table of named test functions. `tests/run.lua` discovers `tests/*_spec.lua`, invokes each function, and reports failures. Run `nvim --clean --headless -l tests/run.lua` from the repository root. Git fixtures use temporary repositories. Tests must check meaningful source/row identities, real Git endpoints, mixed selections, refresh cancellation, expansion and window cleanup. Attached UI checks cover actual display and normal/visual interaction.
